Key Takeaway 1

Headless Agent Experiences Are a Major Theme

Headless Experience

  • Experience is not tied to one Salesforce screen.
  • Agents can surface in Slack, web, mobile, Claude, or custom apps.
  • The interface changes; Salesforce remains the workflow/data engine.

MCP + Agent Workflows

  • MCP was shown as a way for agents to connect to tools and systems.
  • Agent workflows were prominent across demos and technical sessions.
  • Salesforce is promoting agent building on its own platform stack.

Any Interface

Agentforce

→

MCP / Tools

Short definition: A headless experience separates the user interface from the backend workflow. Users may interact through Slack, Claude, a website, or another app while Salesforce powers the data, permissions, workflow, and agent actions behind the scenes.
Key Takeaway 2

Slack Is the Preferred Agentic Work Surface

Strong Salesforce + Slack Native Integration

  • Slack positioned as the collaboration layer for agents.
  • Agentic development is heavily promoted through Slack workflows.
  • Best fit for alerts, approvals, summaries, and team handoffs.

Microsoft Teams Integration Appears Less Mature

  • No visible Microsoft presence in the enterprise section observed.
  • Teams was not highlighted as the primary agentic interface.
  • Integration may require more validation before enterprise rollout.

Key Takeaway 3

AIforce Branding Is Most Visible Through Claude

Claude / Claudeforce

  • Official Salesforce launch centers Claude via Claudeforce.
  • Salesforce in Claude brings CRM context and sales skills into Claude.
  • Claude docs confirm support in Claude Cowork.

ChatGPT / Gemini

  • AIforce is described as open to any AI interface.
  • Salesforce references OpenAI and Google in the ecosystem.
  • Event messaging made Claude more explicit than ChatGPT or Gemini.
Verified: Claude is the clearest branded integration path: Claudeforce and Salesforce in Claude. ChatGPT and Gemini are visible in AIforce's broader open-interface ecosystem, but were less obvious in the primary launch narrative.
Key Takeaway 4

Zero-Copy Integration with Snowflake and Databricks

Snowflake

  • Salesforce Data 360 supports zero-copy sharing with Snowflake.
  • Data can be queried without ETL pipelines or duplication.
  • Useful for analytics, ML, and AI apps using Salesforce context.

Databricks

  • Data 360 supports zero-copy access patterns for Databricks.
  • Databricks lists Data 360 zero-copy connectors as alternatives to ingestion.
  • Good fit for lakehouse analytics and AI/ML workloads.

Verified: Salesforce, Snowflake, and Databricks documentation support zero-copy integration patterns. Practical takeaway: less ETL, less duplication, fresher data; setup, permissions, and governance still need architecture review.

Top Recommendations

Prioritize ROI, Fit, Partners, and Data

1

Adopt Selectively, Then Use Consistently

Even 10-15% of the demonstrated features can deliver high ROI if implemented well and used consistently.

2

Let Sales Use Cases Drive Stack Choices

Many features are superfluous for our industry and growth stage. Choose products based on concrete Sales workflows.

3

Use Enterprise Partners for Complex Logic

Agentic use cases with complex business rules will likely require experienced implementation partners.

4

Prioritize the Integrated Data Layer

Highest value: extract relevant Salesforce account data in Snowflake, analyze on Databricks, and use zero-copy access for an agentic application.
